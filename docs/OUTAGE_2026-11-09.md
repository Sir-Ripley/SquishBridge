## Fixes shipped (v0.6.0, 88/88 tests green)

- **Autostart, no hand commands:** Startup shortcut + `SquishBridge-Watchdog`
  task (every 15 min; `start` is a no-op when healthy). Proven by drill:
  killed the server, watchdog alone revived it (v0.6.0, pid 12756).
- **P0 #2:** `bridge/bridge.config.json` (created on first boot, env >
  file > defaults) + startup `verifyBind` that SHOUTS the loopback-only
  footgun with the fix. Proven by restart drill with zero env vars.
- **P0 #3:** server tracks `last_command_at` (trusted hits only; on
  `/v1/status` + authed WS `status`, never public `/health`); popup always
  shows `bridge <state> · Squish link <active 12s ago|silent 22m|unknown>`.
- **P0 #4:** proven already-shipped — `/v1/devices` still lists
  `ext-776b…` after restart; only explicit revoke clears it.
- **P1 #8:** already shipped — `GET /v1/audit?limit=N` exists and logs no
  payload values (method/path/status/origin only).
- Docs: `INSTALL.md` §4b (autostart + "agents: the ONLY restart" box),
  troubleshooting rows for empty-reply/timeout; README stale bind line
  fixed. `BRIDGE_FIX_BRIEF` + `V06_BRIEF` kept as the record.
